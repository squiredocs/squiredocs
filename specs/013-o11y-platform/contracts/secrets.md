## Delivery topology (two distinct planes)

- **Cluster plane (k8s)**: the Collector mounts `postgres-secret` / `redis-auth`
  (existing SOPS secrets) for its PG/Redis receivers, and mounts the plaintext CA
  ConfigMap for its exporter trust. No new datastore credentials created (G3).
- **Node plane (bare EC2, no k8s)**: OpenObserve's root creds and the server cert/key
  reach the node via the ops track — SOPS-decrypted and rendered to an
  `EnvironmentFile` + `/etc/openobserve/tls/` during provisioning (SSM / cloud-init
  consuming ops-placed material), **not** through a Kubernetes Secret. The
  `o11y-tls.enc.yaml` / `openobserve-root.enc.yaml` files hold the review-visible
  **shape** and are the SOPS home for the private material.

## What THIS feature commits (authoring-only)

- **Scaffold** `*.enc.yaml` files: correct structure + key names, with
  placeholder/empty values or a committed `.example` (mirroring the existing
  `*.yaml.example` convention). Real values are ops-generated and `sops -e`-encrypted
  — the authoring agent has no age private key and does not generate the CA/creds
  (scope + overrides).
- The plaintext CA-trust ConfigMap **structure** (the ops track pastes the real CA
  cert; a public cert is not a secret).
- Documented generation commands (openssl/cfssl for the CA + server cert; a
  root-password mint) live in the FR-029 ops docs.

## Invariants review asserts (SC-004)

- 0 plaintext secret **values** (credentials, private keys) added to git.
- Every new `k8s/secrets/*.enc.yaml` matches the `.sops.yaml` creation rule
  (`encrypted_regex: ^(data|stringData)$`) once the ops track encrypts it; scaffolds
  are clearly marked and carry no real value.
- The CA **certificate** (public) may be committed plaintext; the CA **key** and
  server **key** never are.
- CA validity ~10y; server cert ~2–3y; expiry dates recorded in ops docs with a
  re-issue path (RD-12) — the in-stack cert-expiry alert watches cert-manager, not
  this CA (promotion-notes follow-up).
