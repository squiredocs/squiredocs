# Data Model: Packaging & Distribution — M3 Wave 1

This feature has no database entities. Its "data model" is the set of **file artifacts** under `distribution/` and their derivation rules — the artifact set the design's principle 2 makes ground truth. Each entity below lists its fields, derivation, validation rules (mapped to FRs), and relationships.

## Entity: Shared content (read-only input)

`distribution/shared/skill.md`, `distribution/shared/onboard.md`

- **Fields**: markdown body; `skill.md` carries YAML frontmatter with `name: squire` and a `description` (≤250 chars, /skills UI cap); `onboard.md` carries frontmatter with a `description`.
- **Derivation**: none — M2-signed-off source of truth.
- **Validation**: MUST NOT be rewritten by this feature (FR-006). Content budgets enforced (RBD-13, re-homed per research R9): skill description ≤250 chars, skill body ≤400 lines, onboard ≤300 lines.
- **Relationships**: sole input to the generated `SKILL.md` and `onboard.md` in every bundle.

## Entity: Plugin manifest

`distribution/claude-plugin/.claude-plugin/plugin.json`

- **Fields**: `name: "squire"` (namespacing, not copy — D2/FR-002); `version: "1.0.0"` (valid semver — RBD-5); `description` = production "Squire Docs" copy in the honest-confident voice; `author.name: "Squire Docs"`.
- **Derivation**: generated by `publish.mjs` from a fixed manifest shape (carried from the M2 assembler, version + copy updated). Deterministic (FR-008).
- **Validation**: passes the pinned plugin JSON schema (FR-009); `name` matches `^[a-z0-9-]+$`; `version` is valid semver; user-facing copy says "Squire Docs" (FR-002/026). The version is the update signal for every downstream ecosystem.
- **Relationships**: keyed to `marketplace.json` (same `name`); its `version` is what FR-013's bump-on-change check guards.

## Entity: Marketplace manifest

`distribution/claude-plugin/.claude-plugin/marketplace.json`

- **Fields**: marketplace `name`, `owner.name: "Squire Docs"`, `metadata.description` (production copy, no rehearsal framing — FR-003), `plugins[]` with one entry `{ name: "squire", source: "./", description }`.
- **Derivation**: generated by `publish.mjs`; deterministic.
- **Validation**: passes the pinned marketplace schema (FR-009); makes the repo its own marketplace so that, once mirrored, `/plugin marketplace add squiredocs/squire-plugin` then `/plugin install squire` installs the plugin (FR-003); listing copy is production, not rehearsal.
- **Relationships**: references the plugin by `name`; the zero-review day-one install path.

## Entity: MCP connection config

`distribution/claude-plugin/.mcp.json`

- **Fields**: `mcpServers.squire = { type: "http", url: "https://squiredocs.com/mcp" }`. Server key MUST be `squire` (FR-004) — the served agents.md one-liner, the onboard `/mcp` coaching, and the harness all key off it (spec Edge Case: server-key mismatch breaks the coached flow).
- **Derivation**: generated by `publish.mjs`; deterministic.
- **Validation**: the `url` field is the ONE field exempt from the byte-match drift assertion (FR-015, the harness overrides it per run); a **separate** assertion pins the committed value to exactly `https://squiredocs.com/mcp` (FR-016) so a dev URL can never ship. Every other byte of the file is drift-asserted.
- **Relationships**: the harness copies this file into a throwaway bundle and rewrites `url` to the dev server, asserting the source is never mutated (R1). It is the single field where the rehearsed artifact and the shipped artifact are allowed to differ (SC-002).

## Entity: Generated skill

`distribution/claude-plugin/skills/squire/SKILL.md`

- **Fields**: byte-faithful copy of `shared/skill.md` + a do-not-hand-edit header inserted AFTER any leading YAML frontmatter (frontmatter stays first so the client honors it — FR-005, spec Edge Case).
- **Derivation**: `withGeneratedHeader(readShared('skill.md'), 'distribution/shared/skill.md')`, header naming the shared source and the regen command `node distribution/publish.mjs` (the M2 transform verbatim, regen string updated).
- **Validation**: byte-matches a fresh regeneration (FR-014); the shared source is unchanged (FR-006).
- **Relationships**: derived from shared skill content; installed as the `squire` skill.

## Entity: Generated command

`distribution/claude-plugin/commands/onboard.md`

- **Fields**: byte-faithful copy of `shared/onboard.md` + the same do-not-hand-edit header after frontmatter; invoked as `/squire:onboard`.
- **Derivation**: `withGeneratedHeader(readShared('onboard.md'), 'distribution/shared/onboard.md')`.
- **Validation**: byte-matches a fresh regeneration (FR-014); shared source unchanged.
- **Relationships**: derived from shared onboard content; the `/squire:onboard` command the design's first-run flow drives.

## Entity: Registry server entry

`distribution/mcp-registry/server.json`

- **Fields**: reverse-DNS `name: "com.squiredocs/mcp"`; remote streamable-HTTP endpoint pointing at `https://squiredocs.com/mcp`; OAuth declaration; version mirroring `1.0.0` where the schema carries one; NO package artifact, NO stdio wrapper (FR-007).
- **Derivation**: generated by `publish.mjs`; deterministic.
- **Validation**: passes the pinned Official MCP Registry server schema (FR-007/009, RBD-7): name format, remote/transport shape, OAuth. Drift-pinned to regeneration (FR-014). Namespace ownership / DNS challenge / actual publish are Sam ops (RBD-7) — CI verifies structure only.
- **Relationships**: the wave-1 baseline every subregistry mirrors; independent of the claude-plugin bundle but generated by the same script from the same version.

## Entity: Pinned JSON schemas

`distribution/schemas/*.schema.json` + `distribution/schemas/SOURCES.md`

- **Fields**: one pinned schema per validated manifest (plugin, marketplace, registry server; `.mcp.json` structural if no upstream schema); `SOURCES.md` records each schema's upstream URL, retrieval date, and refresh procedure.
- **Derivation**: vendored (copied) from upstream, pinned (RBD-4). Not generated from `shared/`.
- **Validation**: used BY the validator, not validated themselves; staleness is caught at Sam's submission + the advisory plugin-dev validator (RBD-4).
- **Relationships**: consumed by `publish.mjs`'s validation gate (FR-009/010); refresh path documented (FR-010).

## Entity: Publish script (behavior, not data)

`distribution/publish.mjs`

- **Exports**: `expectedFiles({ endpoint })`, `assembleBundle({ outDir, endpoint })`, `PROD_ENDPOINT`, `withGeneratedHeader`, `DEFAULT_CLAUDE_PLUGIN_DIR` (+ per-channel descriptors) — the programmatic interface the harness and drift test share (FR-008).
- **Modes**:
  - **default (dry-run)**: regenerate every wave-1 bundle from `shared/` + validate against pinned schemas + attempt advisory validator agent. No network, no side effects (FR-012, RBD-6). Exit non-zero naming the offending file + problem on any schema violation (FR-009).
  - **`--publish` + configured remotes**: additionally commit + push each mirror with a message referencing the source commit (FR-012); refuse if content changed but version unchanged (FR-013); fail closed if remotes missing/unreachable (RBD-6). Never exercised by tests/CI against a real remote.
- **State transitions**: `shared/` edit → regenerate → validate → (publish path only) version-bump check → push. Content-changed-but-version-unchanged is a terminal refuse state in the publish path.

## Entity relationship summary

```
shared/skill.md  ──withGeneratedHeader──▶ claude-plugin/skills/squire/SKILL.md
shared/onboard.md ─withGeneratedHeader──▶ claude-plugin/commands/onboard.md
                                          claude-plugin/.claude-plugin/plugin.json ◀── fixed shape + v1.0.0
                                          claude-plugin/.claude-plugin/marketplace.json ◀── fixed shape
                                          claude-plugin/.mcp.json (squire → prod; url drift-exempt)
                                          mcp-registry/server.json (com.squiredocs/mcp)
publish.mjs ──generates+validates──▶ (all above) ──drift-matched by──▶ bundle-drift.test.mjs
schemas/*.schema.json ──validate──▶ manifests
harness ──throwaway copy, url→dev──▶ (rehearses claude-plugin, source unmutated)
```
