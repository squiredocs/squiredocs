## Design Context

### Users
Anyone who uses Google Docs — writers, teams, knowledge workers. Broad, non-technical audience. They come to Squire Docs to write and think, not to configure tools. Their context is focused work: drafting, editing, collaborating. The job is to remove friction between thinking and writing, making AI a natural part of the process rather than a separate destination.

### Brand Personality
**Precise, seamless, confident.**

Squire Docs should feel like a sharp tool in your hand — not flashy, not invisible, but *competent*. The interface communicates that it knows what it's doing, so you can focus on what you're doing. There's quiet confidence in how things are laid out, how transitions feel, how controls respond.

- **Voice**: Direct, clear, no filler. Says what it means in as few words as possible.
- **Tone**: Professional but not corporate. Warm enough to feel human, precise enough to feel trustworthy.
- **Emotional goal**: When a user sits down to write, they should feel *capable* — like the tool is amplifying their abilities, not adding overhead.

### Aesthetic Direction
**Visual tone**: Precise and confident, like Linear — but approachable enough for a non-technical audience. Clean geometry, deliberate spacing, restrained color. Every element earns its place.

**References**:
- **Google Docs**: Familiarity, zero learning curve, the document-as-interface pattern
- **Cursor / Claude Code**: The feeling of AI woven into the workflow so naturally that going back feels broken
- **Linear**: Precision, confidence, polish — how a tool can feel opinionated and sharp without being cold

**Anti-references**:
- **Microsoft Word**: Bloated chrome, endless toolbars, the tool competing with the content for attention
- **TextEdit**: Too stripped — no personality, no sense that the tool is working for you

**Theme**: Light only. White surfaces, tinted grays for depth, purple as the primary accent that distinguishes Squire Docs from the blue/green landscape of productivity tools.

### Design Principles

1. **The document is the interface** — Minimize chrome. Content dominates the viewport. Tools appear contextually and stay out of the way. If it's not helping the user write, it's in the way.

2. **Precision over decoration** — Every pixel is intentional. Spacing is consistent. Colors have semantic meaning. Animations communicate state, never decorate. No gratuitous visual effects.

3. **AI is a collaborator, not a feature** — The AI panel docks beside the document, never on top of it. AI edits appear inline with attribution. The integration should feel so natural that the old copy-paste workflow feels broken in hindsight.

4. **Everything is reversible** — Full version history, clear attribution, one-click restore. Users should never fear making changes or letting AI make changes. Confidence comes from knowing you can always go back.

5. **Familiar patterns, progressive complexity** — Standard document editor conventions for the core experience. Advanced features (AI, version history, sharing, MCP, BYOK) are discovered as needed, never forced upfront. A new user should be productive in seconds.
